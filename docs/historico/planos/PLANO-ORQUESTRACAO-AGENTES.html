2. Arquitetura de Orquestração

O Hermes é o orquestrador. Ele delega tarefas para os outros agentes e integra os resultados. Cada subagente trabalha em seu próprio worktree ou diretório para evitar conflitos.

# Worktrees isolados — um por agente/tarefa
worktree/controle-popular-hermes/   ← Hermes (main, commits diretos)
worktree/controle-popular-opencode/ ← OpenCode (branch próprio)
worktree/cutiazinha-antigravity/    ← Antigravity (branch próprio)
worktree/foz-juris-needle/          ← Needle via Ollama (triagem/classificação)

Comunicação entre agentes: via arquivos de handoff (markdown/YAML) + Telegram. Cada agente escreve seu relatório em worktree/<projeto>/.agents/<nome>/

2.1 Instalação — Passo a Passo

2.1.1 — Iniciar Ollama

# Começar o serviço do Ollama (Windows: via programas ou systemctl)
tasklist | grep ollama 2>/dev/null || (ollama serve &)
sleep 2
curl -s http://127.0.0.1:11434/api/tags | head -5  # deve retornar JSON

2.1.2 — Download do Needle (cactus-compute/needle)

# Needle: micromodel 26M params, tool-calling, distillado de Gemini
# Fonte: https://github.com/cactus-compute/needle  (10k+ stars)

# Opção A — via pip (engine + SDK Python)
pip install "cactus-needle[train]"

# Opção B — via Ollama (importar os pesos para GGUF)
# Primeiro baixe os pesos .safetensors/.gguf de cactuscompute.com/needle
# Depois:  ollama create needle -f Modelfile

# Verificar:
curl -s http://127.0.0.1:11434/api/generate \
  -d '{"model":"needle","prompt":"test","stream":false}' | head -5

2.1.3 — Instalar Antigravity CLI (agy)

# Google Antigravity — CLI para agentes Gemini
# Fonte: https://antigravity.google/docs/cli-overview
pip install google-antigravity  # ou download do instalador desktop

# Verificar auth:
agy --version
# Autenticar com Google Cloud:
gcloud auth application-default login
# Listar modelos:
agy models list

Nota: A Google API já está autenticada em OpenCode. Para usar via genai Python, exporte:

export GOOGLE_API_KEY="AIza..."  # do scripts/.env (nunca imprimir)

3. Workflow Cíclico

🔁 Cada iteração cicla por estas 7 fases. O Hermes orquestra e decide quando re-executar.

1. SUGERIR
→
2. PLANEJAR
→
3. EXECUTAR
→
4. AVALIAR
→
5. RE-EXECUTAR
→
6. ATUALIZAR
→
7. MONITORAR

Fase 1 — SUGERIR Needle/Ollama

  • Who: Needle (triagem), Hermes (decisão)
  • O que: Varre sementeiraprojetos.com.br + GitHub para ideias
  • Método: Needle classifica issues, bugs e oportunidades por impacto. Hermes prioriza.
  • Saída: .agents/sugestoes/ — ranked list + prioridade

Fase 2 — PLANEJAR Antigravity

  • Who: Antigravity (Gemini 3.8 Flash)
  • O que: Lê AGENTS.md de cada projeto + docs/planos/ + sementeiraprojetos.com.br
  • Método: Gera plano detalhado (milestones, riscos, testes, dependências)
  • Saída: docs/planos/PLANO-<tarefa>.html + .agents/<agente>/PLANO.md

Fase 3 — EXECUTAR OpenCode Go

  • Who: OpenCode Go (gpt-oss-20b)
  • O que: Implementa o plano — código, testes, refatoração
  • Método: opencode run '...' --model opencodestorage/gpt-oss-20b --worktree <branch>
  • Saída: Worktree com código + testes passando

Fase 4 — AVALIAR Hermes Antigravity

  • Who: Hermes (auditoria) + Antigravity (review criativa)
  • O que: Hermes roda tsc, vitest, CodeScene, CPF check. Antigravity revisa qualidade, acessibilidade, docs.
  • Saída: .agents/<agente>/AVALIACAO.md — pass/fail + issues

Fase 5 — RE-EXECUTAR (se falhar)

  • Quem: Hermes decide · OpenCode re-executa
  • Gatilho: Qualquer teste, lint, CPF check ou CodeScene falhar
  • Método: Loop com feedback direcionado · máximo 3 iterações

Fase 6 — ATUALIZAR Hermes

  • Who: Hermes (commit + push)
  • Regra: Commit por pathspec, mensagem em arquivo, sempre pushar, nunca --force
  • Trailer: Co-Authored-By: <modelo> <provedor> + Co-Authored-By: <agente> <plataforma>
  • Telegram: sendPhoto com print + texto puro (3 linhas: etapa concluída, próxima, risco/tempo)

Fase 7 — MONITORAR Antigravity

  • Who: Antigravity (pesquisa) + Needle (triagem local)
  • O que: Busca notícias, novos modelos open-source, updates de deps
  • Método: Antigravity usa web + arXiv + GitHub · Needle tria resultados localmente
  • Saída: docs/planos/MONITORAMENTO-<data>.md
  • Cadência: Diário (notícias rápidas) · Semanal (modelos/integridade)
